## Overview

Confect's `next` channel tracks the [Effect 4 beta](https://github.com/Effect-TS/effect-smol). This guide walks every breaking change that Confect packages relay to your app code.

<Warning>
  Effect 4 is still in beta. Confect's `next` channel is pinned to `effect@4.0.0-beta.67`. Expect minor renames to land until Effect 4 stabilizes; we will note them in subsequent prereleases.
</Warning>

<Note>
  Effect's own migration material is the canonical reference for non-Confect APIs:

  - [Effect 4 Schema migration guide](https://github.com/Effect-TS/effect-smol/blob/main/migration/schema.md)
  - Effect 4 d.ts ground truth: `node_modules/effect/dist/{Schema,SchemaAST,Effect,Stream,Layer,Result,Cause,Queue,Context,ConfigProvider,Clock}.d.ts`

  This guide focuses on the patterns Confect users hit most often.
</Note>

Confect prereleases ship from the [`effect4-modernize`](https://github.com/rjdellecese/confect/tree/effect4-modernize) branch under the npm `next` dist-tag, alongside Effect 3 on `latest`. When Effect 4 stabilizes, the branch exits prerelease mode and merges into `main`.

## Why upgrade

Effect 4 unifies the surface that v3 spread across companion packages. For Confect users the immediate wins are:

- **`effect/unstable/*` consolidation** — `@effect/platform`, `@effect/cluster`, `@effect/rpc`, `@effect/sql`, `@effect/workflow`, `@effect/experimental`, `@effect/typeclass`, `@effect/vitest`, and `@effect/cli` have all folded into the main `effect` package under `effect/unstable/*`. One install, one version pin.
- **`Result` replaces `Either`** — narrower API surface, friendlier accessor names (`.success` / `.failure`), and `Effect.result` ergonomics.
- **Unified `Stream.callback`** — the v3 family of `Stream.async{,Scoped,Effect,Push}` collapses into a single function that takes a `Queue`. Confect's WebSocket client is already on this and you can drop the old `unwrapScoped` boilerplate.
- **Simpler service shape** — `Context.Service<Self, Shape>()(name)` replaces the v3 `Effect.Service` class block and the `Context.GenericTag` factory. One canonical form.
- **Typed errors via `Schema.TaggedErrorClass`** — replaces `Schema.TaggedError`. Same ergonomics, less footgun around class generics.

## Breaking changes — Schema API

| v3 | v4 | Notes |
|---|---|---|
| `Schema.Schema<A, I>` | `Schema.Codec<A, I, never, never>` | Two extra type parameters — `DecodingServices` and `EncodingServices`. Most call sites only ever care about the first two. |
| `Schema.Schema.AnyNoContext` | `Schema.Codec<any, any, never, never>` | The `AnyNoContext` shorthand is gone. |
| `Schema.Schema.Type<typeof X>` | `typeof X.Type` | Schemas now expose `.Type` and `.Encoded` directly. |
| `Schema.Schema.Encoded<typeof X>` | `typeof X.Encoded` | — |
| `Schema.encode(s)(x)` | `Schema.encodeEffect(s)(x)` | The bare `encode` / `decode` were renamed to flag that they return `Effect`. |
| `Schema.decode(s)(x)` | `Schema.decodeEffect(s)(x)` | — |
| `Schema.encodedSchema(s)` | `Schema.toEncoded(s)` | — |
| `Schema.typeSchema(s)` | `Schema.toType(s)` | — |
| `Schema.optionalWith(s, { exact: true })` | `Schema.optionalKey(s)` | The `exact` overload is now the dedicated function. |
| `Schema.extend(a, b)` | `a.pipe(Schema.fieldsAssign(b.fields))` | Operates on `fields` instead of the schema as a whole. |
| `Schema.Union(a, b, c)` | `Schema.Union([a, b, c])` | Array form only. |
| `Schema.Literal("a", "b")` | `Schema.Literals(["a", "b"])` | Plural name + array form. `Schema.Literal` still exists for single literals. |
| `Schema.TaggedError` | `Schema.TaggedErrorClass` | Same ergonomics, requires the explicit `Self` generic. |
| `Schema.URL` (string-accepting) | `Schema.URLFromString` | In v4, `Schema.URL` is `instanceOf<globalThis.URL>`. Use `URLFromString` for the v3 behaviour. |
| `Schema.annotations({...})` | `Schema.annotate({...})` | — |
| `ParseResult.ParseError` | `Schema.SchemaError` | The whole `ParseResult` module is no longer exported. |
| `Symbol.for("X")` annotation key | string key like `"@confect/<pkg>/X"` | Annotation keys must be strings. |

### Worked example — function args type

The single most common Confect change is dropping `Schema.Schema.Type` for the inline `.Type` accessor.

<CodeGroup>

```ts v3
import { Schema } from "effect";

const Args = Schema.Struct({ id: Schema.String });

const handler = (a: Schema.Schema.Type<typeof Args>) =>
  Effect.succeed(null);
```

```ts v4
import { Schema } from "effect";

const Args = Schema.Struct({ id: Schema.String });

const handler = (a: typeof Args.Type) =>
  Effect.succeed(null);
```

</CodeGroup>

### Worked example — typed errors

`Schema.TaggedError` becomes `Schema.TaggedErrorClass`. The class name appears twice (once for the generic, once for the tag) — that's intentional and lets the class reflect a sound `Self` type.

<CodeGroup>

```ts v3
import { Schema } from "effect";

export class NoUserIdentityFoundError extends Schema.TaggedError<NoUserIdentityFoundError>()(
  "NoUserIdentityFoundError",
  {},
) {}
```

```ts v4
import { Schema } from "effect";

export class NoUserIdentityFoundError extends Schema.TaggedErrorClass<NoUserIdentityFoundError>()(
  "NoUserIdentityFoundError",
  {},
) {
  get message(): string {
    return "No user identity found";
  }
}
```

</CodeGroup>

### Worked example — extending struct fields

`Schema.extend(a, b)` is removed in favour of acting on `fields` directly.

<CodeGroup>

```ts v3
const Base = Schema.Struct({ id: Schema.String });
const Extended = Schema.extend(
  Base,
  Schema.Struct({ name: Schema.String }),
);
```

```ts v4
const Base = Schema.Struct({ id: Schema.String });
const Extended = Base.pipe(
  Schema.fieldsAssign({ name: Schema.String }),
);
```

</CodeGroup>

## Breaking changes — SchemaAST

If you walked the AST in v3 — say, in a custom validator — most tag names changed.

| v3 | v4 |
|---|---|
| `TypeLiteral` | `Objects` |
| `TupleType` | `Arrays` |
| `StringKeyword` | `String` |
| `NumberKeyword` | `Number` |
| `BooleanKeyword` | `Boolean` |
| `BigIntKeyword` | `BigInt` |
| `UnknownKeyword` | `Unknown` |
| `AnyKeyword` | `Any` |
| `SymbolKeyword` | `Symbol` |
| `UndefinedKeyword` | `Undefined` |
| `VoidKeyword` | `Void` |
| `NeverKeyword` | `Never` |
| `Enums` | `Enum` |
| `SchemaAST.isUndefinedKeyword` | `SchemaAST.isUndefined` |
| `SchemaAST.getAnnotation<T>(key)(ast)` returning `Option` | `Option.fromNullishOr(SchemaAST.resolveAt<T>(key)(ast))` |

`Null` is now its own tag (was bundled under literals in v3).

## Breaking changes — Effect / Stream / Layer / Result / Context

| v3 | v4 | Notes |
|---|---|---|
| `Context.GenericTag<T>(name)` | `Context.Service<Shape>(name)` | One-stage form for function-style keys. |
| `class Foo extends Effect.Tag("Foo")<Foo, Shape>() {}` | `class Foo extends Context.Service<Foo, Shape>()("Foo") {}` | Two-stage form for class-style services. |
| `Effect.Service<Self>()(name, { effect, dependencies, accessors })` | `Context.Service<Self, Shape>()(name)` + `Layer.effect(tag, eff).pipe(Layer.provide(deps))` | The all-in-one v3 helper splits into a tag and a layer. |
| `Context.Reference` (class extension) | `Context.Reference<Service>(key, { defaultValue })` (function form) | — |
| `Effect.Effect.Success<T>` | `Effect.Success<T>` | Same for `.Error<T>` and `.Context<T>`. |
| `Effect.either(eff)` | `Effect.result(eff)` | Returns `Effect<Result<A, E>>` instead of `Effect<Either<E, A>>`. |
| `Effect.catchAll(f)` | `Effect.matchEffect({ onFailure, onSuccess })` | `catchAll` is removed in v4. |
| `Effect.catchTag("ParseError", ...)` | `Effect.catchTag("SchemaError", ...)` | The tag string changed alongside the type. |
| `Effect.dieMessage(msg)` | `Effect.die(msg)` | — |
| `Effect.withClock(clock)(eff)` | `Effect.provideService(Clock.Clock, clock)(eff)` | — |
| `Effect.if` | ternary or `Effect.flatMap` | The helper is removed. |
| `Clock.make()` | inline custom `Clock` literal | No factory; method names also flipped to `…Unsafe` suffix (`currentTimeMillisUnsafe`). |
| `Stream.asyncScoped((emit) => ...)` | `Stream.callback((queue) => Effect)` | Single unified API. |
| `Stream.unwrapScoped(eff)` | `Stream.unwrap(eff)` | Scope is part of the type signature. |
| `emit.single(x)` | `Queue.offerUnsafe(queue, x)` | — |
| `emit.fail(e)` | `Queue.failCauseUnsafe(queue, Cause.fail(e))` | — |
| `Stream.runCollect` returns `Chunk<A>` | returns `Array<A>` | Drop the `Chunk.toArray` wrapper at call sites. |
| `Layer.scoped(tag, eff)` | `Layer.effect(tag, eff)` | v4 auto-manages `Scope` in the type. |
| `Layer.setConfigProvider(p)` | `Layer.succeed(ConfigProvider.ConfigProvider, p)` | — |
| `Layer.map(layer, f)` | `Layer.effect(tag, Effect.map(Effect.service(oldTag), f)).pipe(Layer.provide(layer))` | — |
| `Either` (module) | `Result` | Imports + branch names change. |
| `Either.getOrThrow(e)` | `Result.getOrThrow(r)` | — |
| `Either.match({ onLeft, onRight })` | `Result.match({ onFailure, onSuccess })` | Accessor names on the values change too: `.left`/`.right` → `.failure`/`.success`. |
| `Option.fromNullable` | `Option.fromNullishOr` | — |
| `Hash.cached(this, value)` | inline `Hash.combine(...)` (no caching) | — |
| `Order.number` | `Order.Number` | All built-in `Order` instances capitalised. |
| `Ref.unsafeMake` | `Ref.makeUnsafe` | The unsafe affix moved to the suffix everywhere. |
| `Array.isEmptyReadonlyArray(arr)` / `Array.isEmptyArray(arr)` | `arr.length === 0` | — |

### Worked example — Result replaces Either

The accessors changed from `.left` / `.right` to `.failure` / `.success`. Narrow with `Result.isSuccess` / `Result.isFailure`.

<CodeGroup>

```ts v3
import { Effect, Either } from "effect";

const program = Effect.either(myEffect).pipe(
  Effect.map((either) =>
    Either.match(either, {
      onLeft: (e) => `failed: ${e.message}`,
      onRight: (value) => `ok: ${value}`,
    }),
  ),
);
```

```ts v4
import { Effect, Result } from "effect";

const program = Effect.result(myEffect).pipe(
  Effect.map((result) =>
    Result.match(result, {
      onFailure: (e) => `failed: ${e.message}`,
      onSuccess: (value) => `ok: ${value}`,
    }),
  ),
);

// Or with manual narrowing:
const inspected = Effect.result(myEffect).pipe(
  Effect.map((result) =>
    Result.isSuccess(result) ? result.success : null,
  ),
);
```

</CodeGroup>

### Worked example — Stream.callback

`Stream.asyncScoped` → `Stream.callback`. The shape moves from an imperative `emit` object to a `Queue` you push to. This pattern is straight from `@confect/js`'s WebSocket client.

<CodeGroup>

```ts v3
import { Effect, Stream } from "effect";

const subscribe = Stream.unwrapScoped(
  Effect.gen(function* () {
    return Stream.asyncScoped<Item, MyError>((emit) =>
      Effect.gen(function* () {
        const unsubscribe = source.onUpdate(
          (item) => emit.single(item),
          (err) => emit.fail(err),
        );
        yield* Effect.addFinalizer(() =>
          Effect.sync(() => unsubscribe()),
        );
      }),
    );
  }),
);
```

```ts v4
import { Cause, Effect, Queue, Stream } from "effect";

const subscribe = Stream.unwrap(
  Effect.gen(function* () {
    return Stream.callback<Item, MyError>((queue) =>
      Effect.gen(function* () {
        const unsubscribe = source.onUpdate(
          (item) => {
            Queue.offerUnsafe(queue, item);
          },
          (err) => {
            Queue.failCauseUnsafe(queue, Cause.fail(err));
          },
        );
        yield* Effect.addFinalizer(() =>
          Effect.sync(() => unsubscribe()),
        );
      }),
    );
  }),
);
```

</CodeGroup>

### Worked example — services and layers

The `Effect.Service` class block is gone. Express a service as a `Context.Service` tag plus a `Layer.effect` (or `Layer.succeed` for a constant value).

<CodeGroup>

```ts v3
import { Context, Effect, Layer } from "effect";

export class Auth extends Effect.Service<Auth>()("@confect/server/Auth", {
  effect: Effect.gen(function* () {
    return {
      getUserIdentity: Effect.promise(() => auth.getUserIdentity()),
    };
  }),
}) {}
```

```ts v4
import { Context, Effect, Layer } from "effect";
import type { Auth as ConvexAuth } from "convex/server";

const make = (auth: ConvexAuth) => ({
  getUserIdentity: Effect.promise(() => auth.getUserIdentity()),
});

export class Auth extends Context.Service<
  Auth,
  ReturnType<typeof make>
>()("@confect/server/Auth") {}

export const layer = (auth: ConvexAuth) =>
  Layer.succeed(Auth, make(auth));
```

</CodeGroup>

### Worked example — `Effect.catchAll` is gone

Use `Effect.matchEffect` with both branches when you need an effectful handler.

<CodeGroup>

```ts v3
const program = doWork.pipe(
  Effect.catchAll((error) => recover(error)),
);
```

```ts v4
const program = Effect.matchEffect(doWork, {
  onFailure: (error) => recover(error),
  onSuccess: (value) => Effect.succeed(value),
});
```

</CodeGroup>

### Worked example — providing a Clock

`Effect.withClock` is removed. Provide `Clock.Clock` via `Effect.provideService` instead.

<CodeGroup>

```ts v3
const program = work.pipe(Effect.withClock(myClock));
```

```ts v4
import { Clock, Effect } from "effect";

const program = work.pipe(Effect.provideService(Clock.Clock, myClock));
```

</CodeGroup>

### Worked example — `ConfigProvider`

`Layer.setConfigProvider` is gone — provide the reference directly.

<CodeGroup>

```ts v3
const layer = Layer.setConfigProvider(myProvider);
```

```ts v4
import { ConfigProvider, Layer } from "effect";

const layer = Layer.succeed(ConfigProvider.ConfigProvider, myProvider);
```

</CodeGroup>

<Note>
  Confect ships `ConvexConfigProvider.make()` for the Convex runtime. Effect 4's `ConfigProvider.fromEnv` defaults to `import.meta.env`, which the Convex bundler cannot statically analyse ([effect-smol#2143](https://github.com/Effect-TS/effect-smol/issues/2143)). The Confect helper passes an explicit `process.env` snapshot to side-step that.
</Note>

## Breaking changes — Convex

| Item | Stable channel | `next` channel |
|---|---|---|
| `convex` peer | `^1.30.0` | `^1.39.0` |
| `convex-test` dev | `^0.0.41` | `^0.0.53` |

Convex 1.31–1.39 changes that affect Confect users:

- **1.31** — explicit-table-id `db.get(table, id)` 4-arg variants. Confect's `DatabaseReader`/`DatabaseWriter` continue to pass through to the native API.
- **1.32** — `PaginationOptions.maximumRowsRead` / `maximumBytesRead`, and a paginate filter callback. Both flow through Confect's `paginate` wrapper.
- **1.36** — `ctx.meta.getFunctionMetadata`, `ctx.meta.getTransactionMetrics`.
- **1.37** — `ctx.meta.getDeploymentMetadata`.
- **1.38** — `ctx.meta.getRequestMetadata`.
- **1.39** — typed env vars in `defineApp` / `defineComponent`.

<Note>
  The `ctx.meta.*` surfaces are not yet exposed as Confect Effect services. Follow-up — see the [tracking task](https://github.com/rjdellecese/confect/pulls).
</Note>

`convex-test` jumped from `0.0.41` to `^0.0.53`. The two notable internal changes:

- **0.0.45** — replaced global state with `AsyncLocalStorage`-scoped state; `TestConvex<SpecificSchema>` now supports union types in inline calls.
- **0.0.47** — isolated function-stack tracking between parallel calls (better component module resolution).

Confect's `@confect/test` wrapper continues to work the same way.

## Breaking changes — package surface

Effect 4 folded several companion packages into `effect/unstable/*`. None of the following are part of Confect's `next` peer dependencies anymore:

- `@effect/platform`, `@effect/platform-node`, `@effect/platform-node-shared`, `@effect/platform-bun`
- `@effect/cluster`, `@effect/experimental`, `@effect/rpc`, `@effect/sql`, `@effect/workflow`
- `@effect/typeclass`
- `@effect/cli`, `@effect/printer`, `@effect/printer-ansi`
- `@effect/vitest` (replaced by `@effect/vitest@4.0.0-beta.67`)

If your app imports from any of these, switch to the `effect/unstable/*` equivalent. The v4 companion `@effect/vitest@4.0.0-beta.67` ships side-by-side with the main `effect` beta — use it as a dev dep for `it.effect` style tests.

## HttpApi notes

<Warning>
  `@confect/server`'s HTTP API surface is **stubbed** on the `next` channel. The implementation is typed as `any` with `TODO(effect4)` markers pending a full rewrite against `effect/unstable/{http,httpapi}`.

  The v4 reshape touches `HttpApi`, `HttpApp`, `HttpRouter`, `HttpApiBuilder.toWebHandler`, `HttpApiScalar.layer`, and `HttpServer.layerContext`. Tracking issue in the [follow-up tasks](#known-gaps-and-follow-ups).

  If your app depends on Confect's HTTP API, pin `@confect/server@^7` against Effect 3 until the rewrite lands.
</Warning>

## Things that stay the same

Confect's public API shape is largely unchanged. You do **not** need to rewrite:

- `Table.make(...)`, `DatabaseSchema.make().addTable(...)`, and the rest of the schema-definition surface.
- `FunctionSpec.publicQuery` / `publicMutation` / `publicAction` and `GroupSpec.make().addFunction(...)`.
- `FunctionImpl.make(api, "group", "name", handler)` and `GroupImpl.make(api, "group")`.
- React hook names — `useQuery`, `useMutation`, `useAction`, `usePaginatedQuery` — and their argument shapes.
- The `_generated/api`, `_generated/services`, and `_generated/refs` output produced by `confect codegen`.
- `confect dev` and `confect codegen` CLI behaviour.

The Confect-specific changes are concentrated in the **types you import from `effect`**, not in Confect's own exports.

## Step-by-step upgrade checklist

<Steps>
  <Step title="Bump peer and dev dependencies">
    Update each consumer package to `effect@4.0.0-beta.67`, `convex@^1.39.0`, `convex-test@^0.0.53`, `@effect/vitest@4.0.0-beta.67`, and the `@confect/*@next` packages. Remove any direct dependency on `@effect/{platform,platform-node,cluster,experimental,rpc,sql,workflow}` — they no longer exist on the v4 channel.

    Pin via `pnpm.overrides` if you're in a monorepo (see [Install](#install)).
  </Step>

  <Step title="Run typecheck and triage by category">
    Run `pnpm tsc --noEmit` (or `tsc --noEmit -p tsconfig.json` per package). Group errors by API category — Schema, Effect, Stream, Layer — and apply the renames in the tables above as a mechanical sweep.
  </Step>

  <Step title="Apply Schema API renames">
    Most call sites just need:

    - `Schema.Schema<A, I>` → `Schema.Codec<A, I, never, never>`
    - `Schema.encode/decode` → `Schema.encodeEffect/decodeEffect`
    - `Schema.optionalWith(s, { exact: true })` → `Schema.optionalKey(s)`
    - `Schema.Union(a, b, c)` → `Schema.Union([a, b, c])`
    - `Schema.TaggedError` → `Schema.TaggedErrorClass`
    - `Schema.annotations({...})` → `Schema.annotate({...})`
    - `ParseResult.ParseError` → `Schema.SchemaError`
  </Step>

  <Step title="Apply Effect / Stream / Layer / Result renames">
    The high-value mechanical replacements:

    - `Either` → `Result` (`.left`/`.right` → `.failure`/`.success`)
    - `Effect.either` → `Effect.result`
    - `Effect.catchAll` → `Effect.matchEffect`
    - `Effect.catchTag("ParseError", ...)` → `Effect.catchTag("SchemaError", ...)`
    - `Effect.withClock(c)` → `Effect.provideService(Clock.Clock, c)`
    - `Layer.scoped` → `Layer.effect`
    - `Stream.asyncScoped` → `Stream.callback`
    - `Stream.unwrapScoped` → `Stream.unwrap`
    - `Stream.runCollect` returns `Array<A>` — drop `Chunk.toArray`
    - `Ref.unsafeMake` → `Ref.makeUnsafe`
    - `Option.fromNullable` → `Option.fromNullishOr`
    - `Order.number` → `Order.Number`
  </Step>

  <Step title="Update annotation keys">
    Replace `Symbol.for("X")` annotation keys with stable string keys like `"@yourapp/<pkg>/X"`. Annotation lookup also changed:

    ```ts
    // v3
    SchemaAST.getAnnotation<T>(key)(ast); // Option<T>

    // v4
    Option.fromNullishOr(SchemaAST.resolveAt<T>(key)(ast)); // Option<T>
    ```
  </Step>

  <Step title="Reshape services to Context.Service">
    Replace `Effect.Service<Self>()(name, {...})` class blocks with the `Context.Service<Self, Shape>()(name)` tag plus an explicit `Layer.effect(tag, eff)` (or `Layer.succeed` for constants). See [the worked example](#worked-example-services-and-layers).
  </Step>

  <Step title="Verify tests">
    The `@effect/vitest@4.0.0-beta.67` companion ships the v4 versions of `it.effect`, `it.scoped`, and assertion utilities. Most test-level changes are mechanical (`Either` → `Result` narrowing, `Schema.TaggedErrorClass` mismatches). If you rely on `Chunk.toArray(Stream.runCollect(...))`, drop the wrapper.
  </Step>

  <Step title="Smoke test against a deployment">
    Run `confect dev` plus `convex dev` and exercise a query, mutation, action, and (if applicable) HTTP endpoint. Watch for ConfigProvider issues if you read environment values — Confect's `ConvexConfigProvider.make()` is the supported path.
  </Step>
</Steps>

## Known gaps and follow-ups

These items are tracked separately from the v4 base port. Each is mechanical and unblocks individually:

<AccordionGroup>
  <Accordion title="@confect/cli port to effect/unstable/cli">
    The CLI is excluded from the `effect4-modernize` workspace. Its dependencies on `@effect/cli` / `@effect/platform-node` / `@effect/printer` are Effect 3-only. A follow-up PR rewrites the entrypoint against `effect/unstable/cli`. Consumers who need codegen on the `next` channel should pin `@confect/cli@^7` (Effect 3) until that lands.
  </Accordion>

  <Accordion title="HttpApi full rewrite">
    `packages/server/src/HttpApi.ts` is stubbed with `any` and `TODO(effect4)` markers. The full rewrite targets `effect/unstable/{http,httpapi}` which reshaped `HttpApi`, `HttpApp`, `HttpRouter`, `HttpApiBuilder.toWebHandler`, `HttpApiScalar.layer`, and `HttpServer.layerContext`.
  </Accordion>

  <Accordion title="ctx.meta.* exposed as Confect services">
    Convex 1.36–1.38 added function/transaction/deployment/request metadata to `ctx.meta`. A follow-up exposes these as Confect Effect services on `ActionCtx`, `MutationCtx`, and `QueryCtx`.
  </Accordion>

  <Accordion title="Polymorphic TableInfo casts">
    `Document.ts`, `DatabaseWriter.ts`, `OrderedQuery.ts`, and `QueryInitializer.ts` carry `as never` casts to satisfy v4's stricter polymorphic schema bounds. Tightening these requires a small generics rework and is tracked as a follow-up.
  </Accordion>

  <Accordion title="Test suite cleanups">
    The Effect 4 port did a mechanical sweep across `packages/*/test/`. A handful of semantic mismatches remain — `Either` → `Result` narrowing in assertions, polymorphic `TableInfo` inference, and a few `Schema.TaggedErrorClass` vs `Codec` shape mismatches. Each is fixable per-callsite without changing runtime behaviour.
  </Accordion>

  <Accordion title="apps/example refresh">
    The example app is excluded from the workspace until the CLI port lands (it consumes generated codegen output and uses runtime patterns we have not ported).
  </Accordion>
</AccordionGroup>

For the canonical port log, commit list, and per-package status table, see [RESUME.md](https://github.com/rjdellecese/confect/blob/effect4-modernize/RESUME.md).
